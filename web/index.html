How it works

One intent, three bids, one card.

Companies buy software at list price while vendors spend a fortune finding them. When an agent does the buying, it already knows exactly what it needs. Let vendors compete for it, and turn their acquisition budget into the buyer's discount.

The approval is issued as the card

The human approves one thing: this vendor, this amount, this currency. That approval is issued as a card whose controls are exactly those terms, so the network, not a policy, decides every charge.

Why a card

The approval is the card.

You approve one thing: this vendor, this amount, this currency, this kind of merchant. Outbid issues that approval as an Airwallex virtual card whose controls are exactly those terms. No policy for anyone to follow, no prompt for an agent to obey: the network checks every charge against the approval at authorization, before money moves.

The vendor can't overcharge. A price hike is declined with the very limit that was approved. The agent can't overspend. It never holds the company card, only one that pays one vendor one amount. Nobody can fake a sale. Every settled charge is reported by the network, not by either party, and that is what releases the vendor's fee.

Almost every software vendor already takes cards, so none of it needs the vendor to integrate anything.

The cheapest bid doesn't automatically win

The agent reads the company's Airwallex balance and upcoming obligations, then projects cash for every bid. If the annual prepay would push cash under the floor in week seven, the best monthly bid wins and a reconsider date is recorded.

When a customer payment lands later, the agent re-runs the same decision on the new balance. The annual deal comes back, with a fresh approval and a fresh card.

Vendors pay only for closed deals

The fee is prepaid, and the charge releases it

The winning vendor prepays an acquisition fee into an escrow on Metal. The first cleared charge on the card is the proof of sale: the escrow splits the fee in one transaction, most of it back to the buyer through Airwallex Payouts, the rest to Outbid. No charge by the deadline, and the fee returns to the vendor.

At renewal, a price hike is declined by the same limit that was approved. Outbid reopens the auction and goes back to the incumbent: match the best new price, or the company switches.

Who sees what

Two consoles. The buyer never shows its hand; the vendor never guesses.

The buyer console is where the company's agent starts: it posts the intent, watches the bids and gives approvals. Each vendor has its own vendor console, where its agent sees the intent, its own bid and, when it wins, the card and the fee. Both fill in live from the same run.

Run it

Three steps to a running auction

Node 20, no build, no dependencies. You need an Airwallex sandbox account and a Metal testnet key; both are free.

1

Get the code

Clone the repository and copy the example environment file. Nothing to install.

$ git clone https://github.com/soarewee/outbid
$ cd outbid
$ cp .env.example .env
2

Add the two sandboxes

At sandbox.airwallex.com, register the business in the United States and name it Sandbox Business so it skips review. Create a Client ID and API key under Account → Developer.

For Metal, an RPC endpoint from the testnet console and a disposable key (cast wallet new) with USDZ from the faucet. Put all of it in .env, and never commit it.

3

Run, then post the intent

Start the demo and open the buyer console. It asks what to buy, and the story plays from there. Open the vendor console beside it to watch the other side.

$ npm run demo -- --wait
→ http://localhost:4780/buyer
→ http://localhost:4780/vendor
